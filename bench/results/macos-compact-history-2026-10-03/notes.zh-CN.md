# 历史行共享属性：实现与测量记录

分支 codex/client-cpu-memory，独立 worktree /Users/linxy/.codex/worktrees/tui-client-cpu/loomtty，提交 eef91f5，基于 main d60c18a。未合入 main、推送或安装。

最新四终端测试中，Loomtty 历史后的客户端约 85 MiB、服务端约 47 MiB。此前分配诊断已确认客户端密集 PackedCell 历史行占约 17 MiB。本候选保留相同历史容量、行宽、颜色、所有 flags、原始字符字节、wrap 元数据及外置 grapheme 映射。属性完全一致且至少 8 格的历史行保存一个完整属性模板和每格 4 个字符字节；混合属性行仍密集存储。不能假定所有文本或行宽都可压缩。

协议新增逐行转换解码入口，共用现有 opcode 状态机与边界验证，只复用一个密集 scratch row，避免先建立整份密集历史再压缩的峰值。完整解码成功后才提交到客户端历史。损坏流丢弃结果；短流保留默认 padding。查看压缩历史时临时还原，live viewport 仍借用原有连续 cells。行访问的 Rust API 返回 Cow；CLI 与 wire protocol 不变。

验证：协议/数据模型/集成测试 396 passed、3 ignored；macOS App Intents 客户端测试 389 passed、1 ignored。新增与原解码器的差分检查覆盖跨行 run、属性、短流、截断和尺寸上界；压缩存储验证原始 UTF-8 字节、颜色/flags、混合属性回退、宽字符、滚动查看、选词和 reflow。cargo fmt、workspace all-targets clippy、App Intents release 构建与 codesign verify 通过，保留现有 warnings。

初版 eef91f5 已完成三对交错 A/B，见 complete-r5。全部 6 次独立启动成功，100×30、同一服务端、同样字体/DPI。保留 10,000 行历史后的实际物理 footprint 中位数 132.174 → 119.470 MiB（−12.703 MiB，约 −9.61%）；三对分别减少 9.63%、9.49%、9.96%。客户端为主要来源，服务端没有替换。

初版全屏 TUI CPU 三对变化 +6.51%、−5.76%、+5.50%；局部 TUI +1.06%、−8.64%、+3.18%。方向不一致，即使中位数较低也不能报告成稳定 CPU 收益。冷启动有离群值，未宣称启动速度提升。DSR 是服务端解析确认，不是显示帧率或输入到像素延迟。

补测发现压缩历史翻阅路径存在逐行临时还原数组。后续 dc4bc2d 改为直接写入 visible_cells 的目标缓冲，移除逐行重复分配/拷贝；完整解码行不再清零 scratch，仅为短流尾部和缺失行补默认值。补充了两种存储表示的截断、padding、前缀保留测试，和结束于整行/半行后仍有缺失历史行的差分验证。协议/App/集成测试 397 passed、3 ignored，扩展后的协议测试单独 94 passed；workspace all-targets clippy、format、App Intents release 与 codesign verify 通过。初版的 native 389 passed、1 ignored 不冒充为此提交重新执行的数量。

history-storage 是五轮交错的存储微基准（100/250 列、统一属性/每格变色）。确认所有输入逐格一致；额外的解压/判断 CPU 成本客观存在，具体数值与限制见该目录。direct-binaries.json 对应最终实现 dc4bc2d 的冻结 GUI；共用主分支 d60c18a 的服务端。最终 GUI A/B 另行存放，不能将 eef91f5 的实测数值说成 dc4bc2d 的。

测试窗口按用户授权通过 CLI 自动前台，不再等待人工确认；没有持续验证窗口遮挡状态。编译干扰检查在启动间及各阶段边界执行，不能证明没有短暂编译落在检查间隙。r5 没有检测到干扰。之前中断的样本全部独立保存：r2 为助手在采样时误执行 cargo fmt，自行作废；r4 检测到短暂 Cargo/Rustc，但第二次读取时已退出，因此没有证据确认实际编译操作。r5 改成单次进程快照捕获检测及命令类别，未放宽拒绝条件。
