# loomtty CPU 优化实测 · 2026-09-30

全屏 TUI 的总 CPU 中位数由 **16.40% 降至 12.88%（下降 21.4%）**；单行更新的中位数基本不变。优化前后各 3 次独立启动、共 120 个有效阶段，保持同一工作负载和帧间隔。

[完整指标](report.md) · [原始数据](results.json) · [终端日志](logs/) · [控制器日志](controller.log) · [脚本快照](scripts/) · [诊断采样](profiles/)

## 本次改动

- 服务端行指纹改用 xxHash64，对完整 PackedCell 一次写入，减少逐字段 SipHash 调用。客户端行缓存也从逐字节 FNV 改用 xxHash64，继续覆盖完整行数据和 grapheme extras。这些指纹只用于内部缓存，不是协议字段。
- 零填充 ASCII 的 PackedCell 解码直接返回字符；其余编码继续验证 UTF-8，包括异常尾字节。
- ASCII 单字符字形缓存使用直接索引，保留字体回退、缺字缓存和非 ASCII 路径。字体切换仍重新创建 TextShaper。
- 字形选择阶段只读取字符、宽度和隐藏标记；颜色与装饰信息留到绘制阶段处理，避免重复解码。连字路径仍保留所需颜色信息。
- 字形 atlas 缓存把 glyph ID、字体类别、字形风格、宽度合并成无歧义的整数键，减少每个 glyph 的多字段哈希；缓存仍使用标准 HashMap。

本轮没有修改帧间隔、同步输出策略、渲染分辨率或输出内容。基线已包含之前的 macOS 内存优化及 PTY 调度优化，因此以下结果只衡量本轮增量。

## CPU

一个 CPU 核为 100%，loomtty 总量包括 GUI 客户端和私有服务端。每次 TUI 工作负载为 600 次更新、目标 60 Hz、约 10 秒；资源采样包含 250 ms 收尾时间。

以下为中位数，括号为三次独立启动的最小–最大值。各组件分别取中位数，不能直接相加还原总量。

| 场景 / 进程 | 优化前，单核 % | 优化后，单核 % | 中位数变化 |
|---|---:|---:|---:|
| 全屏 TUI / 合计 | 16.40 (14.17–17.63) | 12.88 (12.10–13.36) | -21.4% |
| 全屏 TUI / 客户端 | 10.30 (9.50–11.14) | 7.91 (7.55–8.66) | -23.3% |
| 全屏 TUI / 服务端 | 6.09 (4.67–6.49) | 4.69 (4.55–4.98) | -23.0% |
| 单行 TUI / 合计 | 8.47 (7.13–8.95) | 8.47 (6.65–8.56) | -0.1% |
| 单行 TUI / 客户端 | 6.24 (5.00–6.56) | 6.26 (4.76–6.35) | +0.4% |
| 单行 TUI / 服务端 | 2.24 (2.13–2.39) | 2.20 (1.89–2.21) | -1.6% |

全屏 TUI 的三组成对比较都降低了总 CPU；单行 TUI 的总量中位数只变化约 0.1%，且范围重叠，不能称为稳定收益。预热后空闲 CPU 两者均约 0.01%。本轮主要减少内容密集更新的计算成本，单行更新仍有窗口、GPU 提交等固定开销。

## 延迟、内存与限制

- 全屏 TUI 的 DSR p95 中位数：0.915 → 0.749 ms；单行 TUI：0.239 → 0.254 ms。所有运行的全屏和单行 TUI 都是 0 次解析响应超期。一次优化后全屏运行的 p95 为 1.723 ms，因此不能声称每次运行都改善延迟。
- 预热后 RSS：114.2 → 113.9 MiB；预热后 physical footprint 中位数：66.3 → 71.4 MiB。但前后的范围分别为 66.3–72.3 与 66.6–72.3 MiB，明显重叠；本次不宣称内存优化。历史填充后的 footprint 为 116.2 → 115.8 MiB。
- 启动到首次 DSR 的中位数为 807 → 913 ms，范围 441–910 与 853–1171 ms；这不是冷启动测试，也没有稳定的启动改善证据。
- DSR 只确认终端解析完成，loomtty 由服务端回复；没有测量 GPU 呈现帧率或按键到像素延迟。CPU 不含 Python workload、WindowServer 和 GPU 执行时间，不能代替整机能耗。
- 三次启动用于给出中位数和范围，不是统计置信区间。系统调度、窗口遮挡和后台负载仍可能影响结果。

## 环境与审计

Apple M6 / 32 GiB / macOS 27.0，交流电；Menlo 10 pt，100×30 网格，**2× DPI、16×31 像素 cell**，800×496 logical pixels。关闭光标闪烁和连字，使用独立配置及状态目录。CPU 改动也通过连字与字体相关测试，但本表不代表开启连字时的性能。

运行顺序为 before/after → after/before → before/after。6 次均有完整 20 阶段，网格和 DPI 相同，6 类 bulk 的字节数及 SHA-256 一致，TUI 更新数和字节数一致。日志审计未发现 panic、配置重载、DPI 变化或工作负载错误。脚本在各阶段前后检查并发 Rust 编译；不能排除检查间隔中的编译或其他系统负载。

确切二进制 SHA-256、脚本 SHA-256、机器状态、配置及 Git 状态均在原始 JSON 中。本机保存的优化前二进制位于 `/tmp/loom-cpu-before-20260930`，优化后位于 `target/release`。所有本次 benchmark 创建的客户端及服务端均已退出。

此前四终端横向报告使用 1× DPI，不能直接把其中的 CPU 数字与本表比较；本次没有重跑或更新竞品排名。

- `cargo test --workspace`：**1,611 passed、0 failed、12 ignored**。
- `cargo clippy --workspace --all-targets`：通过，保留现有 warnings；`cargo fmt --check`、`git diff --check`：通过。
- 新增或扩展的回归验证覆盖：异常 UTF-8 尾字节、ASCII 缓存与原始字体回退结果一致、行首/行尾及颜色/标记变化触发行指纹更新、字形键各维度互不混淆。
- 现有增量渲染、滚动缓存、CJK / Emoji、连字、协议及服务端测试均通过。

构建、测试和 Clippy 日志见 [validation](validation/)。代码仍在 `codex/new-branch` 的未提交修改中，基于已合入 macOS 修复的 `fe438ab`。
